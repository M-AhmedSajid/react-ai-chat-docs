# RAG

RAG, or retrieval augmented generation, lets your chatbot answer questions using your own content.

`react-ai-chat` handles the retrieval step on the server. Your documents are converted into embeddings, stored in an index, and searched when a user sends a message.

The overall flow is:

```text
Your documents
      ↓
Chunking
      ↓
Embeddings
      ↓
Embedding index
      ↓
User question
      ↓
Query embedding
      ↓
Similarity search
      ↓
Relevant context
      ↓
AI model
      ↓
Answer
```

## How RAG works

There are two stages.

### 1. Generate the embedding index

Create an embedding index from your content with the CLI:

```bash
npx react-ai-chat --google
```

By default, the CLI reads:

```text
./content
```

and writes:

```text
./chatbot/embeddings.json
```

You can provide custom paths:

```bash
npx react-ai-chat --google ./docs ./data/embeddings.json
```

The CLI loads your documents, splits them into chunks, generates an embedding for each chunk, and saves the resulting index.

See [CLI](/docs/guides/cli) for the complete command reference.

### 2. Retrieve context during chat

Your API route passes the generated index and an embedding function to `createChatRoute()`:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
  },
});
```

When a user sends a message, the server creates an embedding for the question and compares it with the vectors in the index.

Relevant chunks are selected and added to the model's context.

The retrieval happens entirely on the server. Your chatbot UI does not need to know that RAG is enabled.

## Create your content

Create a directory containing the material your chatbot should search.

For example:

```text
content/
├── getting-started.md
├── installation.md
├── configuration.md
└── faq.md
```

You can use documentation, FAQs, product information, guides, project information, or other text content.

The CLI processes supported files from the content directory and creates the embedding index from them.

## Generate the index

Choose an embedding provider.

For example, with Google:

```bash
npx react-ai-chat --google
```

With a custom content directory:

```bash
npx react-ai-chat --google ./docs
```

With custom input and output paths:

```bash
npx react-ai-chat --google ./docs ./data/embeddings.json
```

You can also use the explicit output option:

```bash
npx react-ai-chat --google ./docs --output ./data/embeddings.json
```

The generated index can then be used by your server route.

## Embedding providers

The CLI supports these embedding providers:

- Google
- OpenAI
- Voyage
- Cohere
- Jina
- Hugging Face

For example:

```bash
npx react-ai-chat --google
```

or:

```bash
npx react-ai-chat --openai
```

or:

```bash
npx react-ai-chat --jina
```

See [Providers](/docs/api/providers) for provider-specific setup.

The provider used to create the index must produce embeddings compatible with the provider used for query retrieval.

## Configure the API route

Once your index has been generated, pass it to `createChatRoute()`.

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
  },
});
```

### `index`

`index` contains the embedding data generated from your documents.

```tsx
rag: {
  index,
}
```

Load the generated index in your server code and pass it to the route.

### `provider`

`provider` is the embedding function used to create the query embedding.

```tsx
rag: {
  provider,
}
```

It should correspond to the embedding provider used when the index was created.

### `topK`

Use `topK` to control how many matching chunks are retrieved:

```tsx
rag: {
  index,
  provider,
  topK: 3,
}
```

For example, `topK: 3` allows up to three relevant chunks to be included in the retrieved context.

If `topK` is omitted, the retrieval system uses its default.

Start with a small value and adjust it based on the quality and amount of context your model needs.

## Generate embeddings with Google

Install the Google GenAI package:

```bash
npm install @google/genai
```

Set your API key:

```text
GOOGLE_GENERATIVE_AI_API_KEY=your_api_key_here
```

Generate the index:

```bash
npx react-ai-chat --google
```

Create the embedding provider on the server:

```tsx
import { GoogleGenAI } from "@google/genai";
import { googleEmbedding } from "react-ai-chat/server";

const client = new GoogleGenAI({
  apiKey: process.env.GOOGLE_GENERATIVE_AI_API_KEY!,
});

const provider = googleEmbedding(client);
```

Then pass the provider to the RAG configuration:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

## Complete example

Start with your content:

```text
content/
├── installation.md
├── configuration.md
└── faq.md
```

Generate the index:

```bash
npx react-ai-chat --google
```

This creates:

```text
chatbot/
└── embeddings.json
```

Load the index in your server route and create the embedding provider:

```tsx
import { GoogleGenAI } from "@google/genai";
import { createChatRoute, googleEmbedding } from "react-ai-chat/server";

import embeddings from "@/chatbot/embeddings.json";

const client = new GoogleGenAI({
  apiKey: process.env.GOOGLE_GENERATIVE_AI_API_KEY!,
});

const provider = googleEmbedding(client);

export const POST = createChatRoute({
  model,
  rag: {
    index: embeddings,
    provider,
    topK: 3,
  },
});
```

Your client can continue using the normal chatbot:

```tsx
"use client";

import { Chatbot } from "react-ai-chat";
import "react-ai-chat/style.css";

export function App() {
  return <Chatbot apiEndpoint="/api/chat" />;
}
```

The client does not require any RAG-specific configuration.

## Retrieval

Suppose a user asks:

```text
How do I configure authentication?
```

The server creates an embedding for the question.

It compares that vector with the vectors stored in the index.

The most relevant chunks are selected:

```text
User question
      ↓
Query embedding
      ↓
Similarity search
      ↓
Relevant chunks
      ↓
Retrieved context
```

The retrieved context is then supplied to the model when generating the response.

The model can use your project documentation as part of its answer.

## Similarity threshold

Retrieval uses vector similarity to determine which chunks are relevant to the question.

The package applies a minimum similarity score when selecting context. Chunks below that threshold are excluded.

This helps prevent unrelated content from being added to the model context.

`topK` controls the maximum number of chunks that can be retrieved after relevance filtering.

## Chunking

Documents are split into smaller chunks before embeddings are generated.

For example:

```text
Large document
      ↓
Chunk 1
Chunk 2
Chunk 3
Chunk 4
      ↓
Embedding for each chunk
```

Smaller chunks allow retrieval to target the relevant part of a document instead of returning the entire document.

Chunking happens when you generate the embedding index.

## Updating your content

The embedding index is generated from your source content.

If you change a document:

```text
content/
└── installation.md
```

regenerate the index:

```bash
npx react-ai-chat --google
```

The old index does not automatically update when your source files change.

For a production workflow, regenerate the index whenever the source content changes.

## RAG with the generated chatbot

RAG works with the generated chatbot as well.

The generated UI sends messages to your API route. Retrieval happens inside that route.

Your server can use:

```tsx
export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

The generated chatbot can continue using:

```text
/api/chat
```

No retrieval logic needs to be added to the client.

## RAG with `<Chatbot />`

The ready-made chatbot works the same way:

```tsx
"use client";

import { Chatbot } from "react-ai-chat";
import "react-ai-chat/style.css";

export function App() {
  return <Chatbot apiEndpoint="/api/chat" />;
}
```

RAG remains a server-side concern.

The chatbot only sends the user's message to `/api/chat`.

## RAG with a custom UI

You can also use RAG with a custom UI built using `ChatbotProvider` and `useChatbotContext()`.

The client-side code remains focused on the chat interface:

```tsx
"use client";

import { ChatbotProvider, useChatbotContext } from "react-ai-chat";

function ChatUI() {
  const { input, setInput, handleSubmit, messages, isLoading } =
    useChatbotContext();

  return <div>{/* Render your custom UI */}</div>;
}

export function CustomChatbot() {
  return (
    <ChatbotProvider apiEndpoint="/api/chat">
      <ChatUI />
    </ChatbotProvider>
  );
}
```

Your server route handles retrieval:

```tsx
export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

This keeps your retrieval implementation independent from your UI.

## Project structure

A typical RAG project can look like:

```text
my-project/
├── content/
│   ├── getting-started.md
│   ├── configuration.md
│   └── faq.md
├── chatbot/
│   └── embeddings.json
├── app/
│   └── api/
│       └── chat/
│           └── route.ts
└── components/
    └── chatbot.tsx
```

The `content` directory contains your source material.

The `embeddings.json` file contains the generated embedding index.

The API route handles chat requests and retrieval.

The client component displays the chatbot.

## Choosing `topK`

`topK` controls the maximum number of chunks retrieved for a question.

For example:

```tsx
rag: {
  index,
  provider,
  topK: 3,
}
```

A smaller value keeps the retrieved context focused.

A larger value gives the model more source material.

Start with a small value and increase it when answers need more context.

Remember that retrieved chunks still need to pass the package's similarity filtering before they are included.

## Troubleshooting

### No relevant context is being retrieved

Check that:

- Your source content was indexed successfully.
- The embedding provider matches the provider used to generate the index.
- The API route is loading the correct `embeddings.json`.
- Your `topK` value is appropriate for the content.
- Your source documents contain information relevant to the user's question.

Regenerate the index after changing your source content:

```bash
npx react-ai-chat --google
```

### The embedding provider does not match

An index generated with one embedding system should be queried with the compatible embedding provider.

For example, if you generated the index with:

```bash
npx react-ai-chat --google
```

use the corresponding Google embedding provider for retrieval.

### The index is outdated

Regenerate it after modifying your documents:

```bash
npx react-ai-chat --google
```
