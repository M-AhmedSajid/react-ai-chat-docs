# RAG

RAG, or retrieval augmented generation, lets your chatbot answer questions using your own content.

Instead of relying only on the model's built-in knowledge, `react-ai-chat` retrieves relevant content from an embedding index and provides it to the model as context.

The flow looks like this:

```text
Your documents
      ↓
Chunking
      ↓
Embeddings
      ↓
Embedding index
      ↓
User question
      ↓
Query embedding
      ↓
Relevant chunks
      ↓
AI model
      ↓
Answer
```

## How RAG works

There are two parts to the RAG workflow.

### 1. Create the embedding index

First, convert your documents into embeddings.

You can use the CLI:

```bash
npx react-ai-chat --google
```

By default, the CLI reads from:

```text
./content
```

and creates:

```text
./chatbot/embeddings.json
```

You can provide custom paths:

```bash
npx react-ai-chat --google ./docs ./chatbot/embeddings.json
```

See [CLI](/docs/guides/cli) for the available options.

### 2. Use the index during chat

Pass the generated index and embedding provider to `createChatRoute()`:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

When a user sends a message, `react-ai-chat` creates an embedding for the question and searches the index for relevant chunks.

Those chunks are then provided to the model as context.

## Create your content

Create a directory for the content you want your chatbot to search.

For example:

```text
content/
├── getting-started.md
├── installation.md
├── configuration.md
└── faq.md
```

Your content can contain documentation, FAQs, product information, guides, or other text that your chatbot should know about.

## Generate the index

Choose an embedding provider.

For example, Google:

```bash
npx react-ai-chat --google
```

Or use a custom content and output path:

```bash
npx react-ai-chat --google ./content ./chatbot/embeddings.json
```

The CLI reads your documents, chunks the content, generates embeddings, and writes the resulting index.

## Embedding providers

`react-ai-chat` supports:

- Google
- OpenAI
- Voyage
- Cohere
- Jina
- Hugging Face

For provider installation and configuration, see [Providers](/docs/api/providers).

For example, with OpenAI:

```bash
npm install openai
```

Then generate the index:

```bash
npx react-ai-chat --openai
```

The provider used to create the index should be the same provider used for retrieval.

## Configure the API route

After generating the index, load it in your server route.

A basic RAG configuration looks like:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
  },
});
```

### `index`

`index` is the embedding index generated by the CLI.

```tsx
rag: {
  index,
}
```

### `provider`

`provider` is the embedding provider used to generate query embeddings.

```tsx
rag: {
  provider,
}
```

### `topK`

`topK` controls how many relevant chunks are retrieved:

```tsx
rag: {
  index,
  provider,
  topK: 3,
}
```

For example, `topK: 3` retrieves up to three relevant chunks.

## Complete example

A complete setup can look like this.

First, create your content:

```text
content/
├── installation.md
├── configuration.md
└── faq.md
```

Generate the index:

```bash
npx react-ai-chat --google
```

Then configure your server route:

```tsx
import { GoogleGenAI } from "@google/genai";
import { createChatRoute, googleEmbedding } from "react-ai-chat/server";

// Load the generated index here.
import { embeddings } from "@/chatbot/embeddings.json"; // your generated embeddings.json path

const index = embeddings;

const client = new GoogleGenAI({
  apiKey: process.env.GOOGLE_GENERATIVE_AI_API_KEY!,
});

const provider = googleEmbedding(client);

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

Your client can continue using the normal chatbot:

```tsx
"use client";

import { Chatbot } from "react-ai-chat";
import "react-ai-chat/style.css";

export function App() {
  return <Chatbot apiEndpoint="/api/chat" />;
}
```

The client does not need any special RAG configuration.

## Retrieval

When a user asks a question:

```text
How do I configure authentication?
```

`react-ai-chat` embeds the question and compares it with the vectors in your index.

Relevant chunks are selected:

```text
configuration.md
     ↓
Authentication section
     ↓
Retrieved context
```

The retrieved context is then passed to the model so it can use your documentation when generating the answer.

## Chunking

Large documents are split into smaller chunks before embeddings are generated.

This makes retrieval more precise because the system can retrieve the relevant section instead of sending an entire document to the model.

The chunking process happens when you generate the embedding index.

If you update your source content, regenerate the index:

```bash
npx react-ai-chat --google
```

## Updating your content

The embedding index is generated from your source files.

If you change your documentation:

```text
content/
└── installation.md
```

regenerate the index so the changes are included:

```bash
npx react-ai-chat --google
```

For production applications, regenerate the index whenever your source content changes.

## Choosing `topK`

`topK` controls the number of chunks retrieved for each question.

For example:

```tsx
rag: {
  index,
  provider,
  topK: 3,
}
```

A smaller value provides less context.

A larger value provides more context.

Start with a small value and adjust it based on the quality of your answers.

## RAG with the generated chatbot

RAG works with the generated chatbot too.

The generated UI sends messages to your API route just like the ready-made `<Chatbot />`.

Configure RAG on the server:

```tsx
export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

Your generated chatbot can continue using:

```text
/api/chat
```

No retrieval code needs to be added to the client.

## RAG with any supported provider

The chatbot UI is independent of the embedding provider.

You can generate an index with Google:

```bash
npx react-ai-chat --google
```

or OpenAI:

```bash
npx react-ai-chat --openai
```

or Jina:

```bash
npx react-ai-chat --jina
```

The API route then uses the corresponding embedding provider for retrieval.

See [Providers](/docs/api/providers) for the complete provider setup.

## Project structure

A typical RAG project can look like:

```text
my-project/
├── content/
│   ├── getting-started.md
│   ├── configuration.md
│   └── faq.md
├── chatbot/
│   └── embeddings.json
├── app/
│   └── api/
│       └── chat/
│           └── route.ts
└── components/
    └── chatbot.tsx
```

The content directory contains your source material.

The embedding index contains the generated vectors.

The API route handles retrieval and chat generation.

The client component displays the chatbot.
