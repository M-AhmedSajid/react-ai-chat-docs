# CLI

`react-ai-chat` includes a CLI for two main tasks:

- Generate an editable chatbot UI
- Create an embedding index for RAG

Run the CLI with:

```bash
npx react-ai-chat
```

You can also run a specific command directly.

```bash
npx react-ai-chat init
```

## Commands

| Command | Purpose                                       |
| ------- | --------------------------------------------- |
| `init`  | Generate an editable chatbot UI               |
| `embed` | Create an embedding index from your documents |

## Generate the chatbot

Run the `init` command to generate an editable chatbot UI:

```bash
npx react-ai-chat init
```

The CLI supports three options:

| Option          | Description                             |
| --------------- | --------------------------------------- |
| `--jsx`         | Generate JSX files instead of TSX files |
| `--path <path>` | Set the output directory                |
| `--force`       | Overwrite existing generated files      |

### Generate TypeScript files

By default, the CLI generates TypeScript React components:

```bash
npx react-ai-chat init
```

The default output directory is:

```text
./chatbot
```

The generated files are:

```text
chatbot/
├── chatbot.tsx
├── chatbot-header.tsx
├── chatbot-messages.tsx
├── chatbot-input.tsx
└── chatbot.css
```

### Generate JSX files

Use `--jsx` when your project uses JavaScript:

```bash
npx react-ai-chat init --jsx
```

This generates:

```text
chatbot/
├── chatbot.jsx
├── chatbot-header.jsx
├── chatbot-messages.jsx
├── chatbot-input.jsx
└── chatbot.css
```

### Change the output path

Use `--path` to choose where the generated files should be placed:

```bash
npx react-ai-chat init --path ./components/chatbot
```

This produces:

```text
components/
└── chatbot/
    ├── chatbot.tsx
    ├── chatbot-header.tsx
    ├── chatbot-messages.tsx
    ├── chatbot-input.tsx
    └── chatbot.css
```

### Overwrite existing files

The CLI protects existing generated files by default.

Use `--force` when you want to overwrite them:

```bash
npx react-ai-chat init --force
```

You can combine the options:

```bash
npx react-ai-chat init --jsx --path ./components/chatbot --force
```

This generates JSX components in `./components/chatbot` and allows existing files to be replaced.

See [Generated Chatbot](/docs/guides/generated-chatbot).

## Create an embedding index

Run:

```bash
npx react-ai-chat embed
```

The CLI uses an interactive setup.

### 1. Select a provider

Choose the embedding provider you want to use.

The available providers are:

- Google
- OpenAI
- Voyage AI
- Cohere
- Jina AI
- Hugging Face

### 2. Select the primary model

The CLI loads the models available for the selected provider.

You can choose the model used to generate the primary embeddings.

### 3. Select dimensions

Some embedding models support multiple output dimensions.

The CLI only presents dimensions supported by the selected model.

The selected dimension is used consistently when generating the index.

### 4. Select a fallback model

You can optionally select a fallback model.

Fallback models are filtered to models that support the same embedding dimensions.

If the primary provider encounters an error while generating a batch, the CLI can switch to the fallback provider configuration for that batch.

### 5. Select the documents directory

Choose the directory containing the documents you want to index.

The current indexing pipeline processes Markdown and MDX content.

### 6. Select the output path

Choose where the generated embedding index should be saved.

The resulting JSON file contains the indexed chunks and embedding metadata.

## Batched embedding generation

The CLI generates embeddings in batches instead of sending every document chunk as an individual request.

Each embedding provider has a configured maximum batch size. The indexer uses that limit when sending chunks to the provider.

For example, if the provider supports a maximum batch size of `32` and your documents produce `70` chunks:

```text
70 document chunks
        ↓
Batch 1: chunks 1-32
        ↓
Batch 2: chunks 33-64
        ↓
Batch 3: chunks 65-70
```

Batches are processed sequentially. This reduces unnecessary API requests and helps reduce rate-limit pressure during large indexing jobs.

### Batch progress

The CLI reports progress while embedding batches:

```text
Embedding batch 1/3: chunks 1-32/70
Embedding batch 2/3: chunks 33-64/70
Embedding batch 3/3: chunks 65-70/70
```

The number of chunks in each batch depends on the provider's configured maximum batch size.

## Example workflow

A typical RAG setup looks like:

```text
Your Markdown / MDX files
          ↓
npx react-ai-chat embed
          ↓
Provider
          ↓
Embedding model
          ↓
Embedding dimensions
          ↓
Optional fallback model
          ↓
Split into batches
          ↓
Generate embeddings
          ↓
Embedding index
          ↓
Your server
          ↓
RAG retrieval
```

## Resumable embedding generation

Embedding progress is saved after each successful batch. This protects long indexing runs from losing completed work if the process is interrupted or the embedding provider stops accepting requests.

If an embedding run is interrupted or stops because of a provider quota or rate limit, run the same command again:

```bash
npx react-ai-chat embed
```

If an incomplete run is found, the CLI asks whether you want to continue from the saved progress or start a new embedding run.

### Continue an incomplete run

Choose **Continue** to reuse the saved embedding configuration and skip chunks that were already embedded successfully.

Each saved chunk is matched using:

- Chunk ID
- SHA-256 hash of the chunk content

If a source chunk has changed since the previous run, it is embedded again.

For example:

```text
Previous run
     ↓
Chunks 1-200 completed
     ↓
Process interrupted
     ↓
Run `npx react-ai-chat embed` again
     ↓
Resume with remaining chunks
```

The CLI keeps the original chunk positions in its progress output:

```text
Embedding batch 1: chunks 201-262/262 via google (gemini-embedding-2)
```

### Start a new run

Choose **Start a new embedding run** when you want to discard the saved progress and generate the index from the beginning.

Temporary embedding progress is stored at:

```text
chatbot/embedding.progress.json
```

The progress file is separate from the persistent embedding configuration:

```text
chatbot/embedding.config.json
```

The progress file is temporary and should not be committed to your repository.

### Changed and removed chunks

When continuing an incomplete run, the CLI compares the saved chunks with the current source documents.

If a chunk's content changed, its old embedding is discarded and the chunk is embedded again.

If a chunk no longer exists in the current documents, its saved progress is removed.

This keeps the saved progress aligned with the current source content.

### Rate limits and interruptions

If the provider continues rejecting requests after the configured retries, the CLI reports how many chunks were generated and how many remain.

For example:

```text
Progress saved:
  Generated: 200 / 262
  Remaining: 62

Run "npx react-ai-chat embed" again to continue from where it stopped.
```

Progress is written only after a batch completes successfully. An interrupted or failed batch is therefore processed again when you continue the run.

After all chunks are successfully embedded, `embeddings.json` is saved and the temporary progress file is deleted automatically.

## Environment variables

The embedding provider needs its API credentials.

Set the appropriate environment variable before running the command.

For example:

```text
GEMINI_API_KEY=your_api_key_here
```

Use the environment variable required by your selected provider.

Do not commit API keys to your repository.

## Re-running the command

Run the embed command whenever your source documents change:

```bash
npx react-ai-chat embed
```

If no incomplete embedding run exists, the CLI starts a new embedding run.

If an incomplete run exists, the CLI asks whether you want to:

- Continue from the saved progress
- Start a new embedding run

When continuing, chunks that were already embedded and have not changed are skipped.

If you change the embedding provider, model, or dimensions, the saved progress cannot be reused with the new configuration. Start a new embedding run with the new configuration.

After a successful run, the generated `embeddings.json` file is saved and the temporary progress file is removed.

## Why dimensions matter

Embedding vectors have a fixed number of dimensions.

For example, an index generated with:

```text
Model: your-model
Dimensions: 768
```

must be queried with vectors that also contain `768` values.

`react-ai-chat` checks vector dimensions during retrieval and reports an error when they do not match.

## CLI and RAG

The CLI only creates the index.

Your server route uses that index during chat requests:

```text
CLI
 │
 ├── Read documents
 ├── Split into chunks
 ├── Create embedding batches
 ├── Generate embeddings
 └── Save index
          │
          ▼
     Embedding index
          │
          ▼
   createChatRoute()
          │
          ▼
      RAG retrieval
          │
          ▼
       AI model
```

See [RAG](/docs/guides/rag) for connecting the generated index to your chat route.

## Troubleshooting

### Provider API key is missing

Make sure the required environment variable exists in the environment where you run the CLI.

### Embedding dimension mismatch

Make sure the query embedding and stored embeddings use the same dimensions.

If you changed the model or dimensions, regenerate the index.

### Embedding provider mismatch

The provider and model used during retrieval must be compatible with the index.

Regenerate the index when changing your embedding configuration.

### Rate limit

Embedding requests are processed in batches to reduce unnecessary API requests and rate-limit pressure.

If a batch fails and a fallback model was configured, the CLI can use the fallback provider configuration to continue processing that batch.

Make sure the fallback model supports the same embedding dimensions as the primary model.
