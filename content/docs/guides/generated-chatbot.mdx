# Generated Chatbot

The CLI can generate the chatbot UI directly into your project.

This is useful when you want control over the component structure, markup, and CSS instead of configuring the ready-made `<Chatbot />` component through props.

## Generate the chatbot

Run:

```bash
npx react-ai-chat init
```

By default, the CLI generates TypeScript React components inside:

```text
./chatbot
```

You can change the output directory with `--path`:

```bash
npx react-ai-chat init --path ./components/chatbot
```

For JavaScript projects, use `--jsx`:

```bash
npx react-ai-chat init --jsx
```

See [CLI](/docs/guides/cli) for all available options.

## Generated files

The default TypeScript generation produces:

```text
chatbot/
├── chatbot.tsx
├── chatbot-header.tsx
├── chatbot-messages.tsx
├── chatbot-input.tsx
└── chatbot.css
```

Each file has a specific responsibility.

### `chatbot.tsx`

This is the main component.

It creates the `ChatbotProvider` and renders the chatbot UI.

```tsx
import { ChatbotProvider } from "react-ai-chat";
import { ChatbotHeader } from "./chatbot-header";
import { ChatbotMessages } from "./chatbot-messages";
import { ChatbotInput } from "./chatbot-input";
import "./chatbot.css";
```

The generated component exposes a small set of configuration props:

```tsx
interface ChatbotProps {
  apiEndpoint?: string;
  position?: "bottom-right" | "bottom-left" | "top-right" | "top-left";
  initialOpen?: boolean;
  themeMode?: "auto" | "light" | "dark";
}
```

The generated component defaults to:

```text
apiEndpoint: /api/chat
position: bottom-right
initialOpen: false
themeMode: auto
```

### `chatbot-header.tsx`

Contains the chatbot header.

The generated header includes:

- Assistant title
- Subtitle
- Close button

The close button uses `useChatbotContext()` to control the chatbot state.

### `chatbot-messages.tsx`

Renders the conversation.

It uses `useChatbotContext()` to access:

- `messages`
- `isLoading`
- `handleSubmit`

Assistant text is rendered with `react-markdown`.

The generated component also includes starter prompts:

```tsx
const starterPrompts = [
  "What is the main tech stack?",
  "Tell me about key projects.",
  "How can I get started?",
];
```

You can replace these prompts with questions relevant to your application.

### `chatbot-input.tsx`

Contains the message input and send button.

It uses:

```tsx
const { input, setInput, handleSubmit, isLoading } = useChatbotContext();
```

The generated input disables submission while a response is loading or when the input is empty.

### `chatbot.css`

Contains the styles for the generated chatbot.

The stylesheet includes:

- Chat window
- Trigger button
- Header
- Message bubbles
- Starter prompts
- Input
- Loading indicator
- Light and dark theme tokens
- Position utilities
- Responsive sizing

You own this stylesheet after generation, so you can modify it freely.

## Using the generated chatbot

Import your generated component from your project:

```tsx
import { Chatbot } from "./chatbot/chatbot";

export default function Page() {
  return <Chatbot />;
}
```

The generated component uses `/api/chat` by default.

If your API route uses another path:

```tsx
<Chatbot apiEndpoint="/api/assistant" />
```

## Position

The generated component supports four positions:

```tsx
<Chatbot position="bottom-right" />
```

```tsx
<Chatbot position="bottom-left" />
```

```tsx
<Chatbot position="top-right" />
```

```tsx
<Chatbot position="top-left" />
```

## Theme mode

The generated component supports:

```tsx
<Chatbot themeMode="auto" />
```

```tsx
<Chatbot themeMode="light" />
```

```tsx
<Chatbot themeMode="dark" />
```

`auto` allows the generated CSS to follow the system color preference.

You can also modify the CSS variables directly in `chatbot.css`.

## Using the context

The generated components use `ChatbotProvider` and `useChatbotContext`.

You can access the chat state inside your own components:

```tsx
import { useChatbotContext } from "react-ai-chat";

function CustomComponent() {
  const {
    messages,
    input,
    setInput,
    isLoading,
    handleSubmit,
    isOpen,
    setIsOpen,
  } = useChatbotContext();

  return (
    <div>
      <p>Messages: {messages.length}</p>
      <p>Loading: {isLoading ? "Yes" : "No"}</p>
    </div>
  );
}
```

This allows you to build your own UI while keeping the package's chat state and request handling.

See [useChatbotContext](/docs/api/use-chatbot-context) for the available context values.

## Customizing the generated UI

The generated files are regular React components.

You can change:

- Header content
- Starter prompts
- Empty state
- Message rendering
- Markdown rendering
- Input behavior
- Loading UI
- Icons
- CSS
- Layout
- Responsive behavior

For example, replace the generated starter prompts:

```tsx
const starterPrompts = [
  "How does pricing work?",
  "What features are available?",
  "How can I contact support?",
];
```

You can also replace the generated header:

```tsx
<header className="chatbot-header">
  <div className="chatbot-header-content">
    <h2>Support Assistant</h2>
    <p>We're here to help</p>
  </div>
</header>
```

## Regenerating the chatbot

The generated files are application source code.

If you run the CLI with `--force`, existing generated files can be overwritten:

```bash
npx react-ai-chat init --force
```

Make sure you have committed or backed up your changes before using `--force`.

## Generated UI vs ready-made UI

The two approaches solve different needs.

The ready-made component:

```tsx
<Chatbot />
```

is the fastest way to add a chatbot.

The generated component gives you the source files:

```text
chatbot/
├── chatbot.tsx
├── chatbot-header.tsx
├── chatbot-messages.tsx
├── chatbot-input.tsx
└── chatbot.css
```

Choose the generated UI when you need to modify the internal structure rather than only configuring the component.
