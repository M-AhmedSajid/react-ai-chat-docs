# Generated Chatbot

The `react-ai-chat` CLI can generate a customizable chatbot directly inside your project.

Run:

```bash
npx react-ai-chat init
```

The generated chatbot is made from regular React components that you own and can modify.

## Generate the chatbot

The basic command generates a TypeScript chatbot:

```bash
npx react-ai-chat init
```

For JSX:

```bash
npx react-ai-chat init --jsx
```

You can choose the output directory:

```bash
npx react-ai-chat init --path src/components/chatbot
```

To replace an existing generated chatbot:

```bash
npx react-ai-chat init --force
```

These options can be combined:

```bash
npx react-ai-chat init --jsx --path src/components/chatbot --force
```

See [CLI](/docs/guides/cli) for all available options.

## Why use the generated chatbot?

The ready-made `<Chatbot />` component is the quickest way to add a chatbot:

```tsx
import { Chatbot } from "react-ai-chat";

<Chatbot apiEndpoint="/api/chat" />;
```

The generated version gives you more control over the implementation.

You can change:

- Component structure
- Layout
- Styling
- Header
- Message rendering
- Input UI
- Trigger UI
- Loading states
- Error states
- Available chatbot controls

This is useful when you want the chatbot to match an existing application design closely.

## Generated components

The generated chatbot uses the package's reusable components rather than implementing chat state from scratch.

The generated code can use components such as:

```tsx
import {
  ChatbotProvider,
  ChatbotTrigger,
  ChatbotWindow,
  ChatbotHeader,
  ChatbotMessages,
  ChatbotInput,
} from "react-ai-chat";
```

The provider manages the chatbot state and makes it available to the child components.

A simplified structure looks like this:

```tsx
<ChatbotProvider>
  <ChatbotTrigger />

  <ChatbotWindow>
    <ChatbotHeader />
    <ChatbotMessages />
    <ChatbotInput />
  </ChatbotWindow>
</ChatbotProvider>
```

The generated implementation can be changed to fit your application's needs.

### Chatbot provider

`ChatbotProvider` provides the state used by the chatbot components.

A basic setup looks like:

```tsx
"use client";

import {
  ChatbotProvider,
  ChatbotTrigger,
  ChatbotWindow,
  ChatbotHeader,
  ChatbotMessages,
  ChatbotInput,
} from "react-ai-chat";

export function MyChatbot() {
  return (
    <ChatbotProvider apiEndpoint="/api/chat">
      <ChatbotTrigger />

      <ChatbotWindow>
        <ChatbotHeader />
        <ChatbotMessages />
        <ChatbotInput />
      </ChatbotWindow>
    </ChatbotProvider>
  );
}
```

The provider connects the UI components to your chat API.

### Customize the header

Because the generated code belongs to your application, you can modify the header directly.

For example:

```tsx
<ChatbotHeader>
  <div>
    <strong>Project Assistant</strong>
    <span>Ask me anything</span>
  </div>
</ChatbotHeader>
```

You can add your own branding, controls, status indicators, or other UI.

### Customize messages

The generated message area can be changed to match your application.

For example, you can customize:

```tsx
<ChatbotMessages />
```

or replace the generated message rendering with your own implementation.

This lets you control how user messages, assistant responses, loading states, and errors appear.

### Customize the input

The generated input component can also be customized:

```tsx
<ChatbotInput />
```

You can change its surrounding layout and styling or build your own input UI using the chatbot context.

For example:

```tsx
<div className="flex gap-2">
  <ChatbotInput />
</div>
```

### Customize the trigger

The trigger controls how users open the chatbot.

You can modify the generated trigger:

```tsx
<ChatbotTrigger />
```

For example, you could replace its contents with your own button design:

```tsx
<button type="button">Ask AI</button>
```

When building a custom trigger, use the chatbot context or the provided trigger component so it remains connected to the chatbot state.

### Customize styling

The generated files can contain their own CSS or use your application's styling system.

You can replace the generated styles with:

- Tailwind CSS
- CSS Modules
- Global CSS
- Your existing design system

The generated code is intended to be edited.

## API endpoint

The generated chatbot still needs a server endpoint.

For example:

```tsx
<ChatbotProvider apiEndpoint="/api/chat">
```

Your endpoint can be created with:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
});
```

See [API Route](/docs/getting-started/api-route).

## RAG

The generated chatbot can use the same API route configuration as the ready-made `Chatbot` component.

For example:

```tsx
import { createChatRoute } from "react-ai-chat/server";

export const POST = createChatRoute({
  model,
  rag: {
    index,
    provider,
    topK: 3,
  },
});
```

The UI does not need to know whether the server uses RAG.

The server handles retrieval before generating the response.

See [RAG](/docs/rag).

## Regenerating the chatbot

Running:

```bash
npx react-ai-chat init
```

does not overwrite existing generated files by default.

If you want to regenerate them, use:

```bash
npx react-ai-chat init --force
```

Be careful when using `--force` after modifying generated files. Your changes can be replaced.

A good approach is to commit your customized chatbot before regenerating it.

## Generated code belongs to your project

After generation, the files are regular source files.

You can:

```text
Edit
  ↓
Commit
  ↓
Customize
  ↓
Deploy
```

You don't need to modify files inside `node_modules` to customize the generated chatbot.

## When to use each approach

Use the ready-made component when you want a chatbot running quickly:

```tsx
<Chatbot apiEndpoint="/api/chat" />
```

Use the generated chatbot when you need control over the individual UI components and their implementation.

Both approaches use the same package and can connect to the same API route.
